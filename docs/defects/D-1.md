# D-1: A directory named `.shelf.json.tmp` beside the shelf makes `done`, `drop` and `add` crash with a stack trace

- Seen: Stage `shelf.json` as {1 to read Dune} and create a directory named `.shelf.json.tmp` beside it. `node app/shelf.mjs done 1` exits 1, prints nothing on stdout, and prints on stderr `shelf: unexpected error`, then `SystemError [ERR_FS_EISDIR]: Path is a directory: rm returned EISDIR (is a directory) .shelf.json.tmp`, then nine stack frames that name the absolute paths of `app/src/store.mjs`, `app/src/shelf.mjs` and `app/shelf.mjs` on the reader's disk. `drop 1` does the same. `add Dune` in a directory holding only that `.shelf.json.tmp` directory does the same and creates no `shelf.json`. In every case `shelf.json` is untouched byte for byte and the directory listing is unchanged, so no data is lost. Cause, read in `app/src/store.mjs` as it stood on main `a9c2f92`: `writeShelf` writes `.shelf.json.tmp` and renames it over `shelf.json`; when the write fails because that name is a directory, the clean-up `fs.rmSync(TEMP_FILE, { force: true })` in the catch block throws a second error on the directory, and that one reaches the boundary unclassified.
- Requires: blueprint section 7, "How the file is written" ("if any step fails, remove the temporary file and report unwritable"); TD-8; blueprint section 10 message table (`unwritable`: exit 1, `shelf: cannot write shelf.json (<error code>)`, stdout empty). PRD REQ-08 c2 and c3 ask for exit 1, a message on stderr and nothing on stdout, which this does meet; the PRD is silent on stack traces and on `.shelf.json.tmp`.
- Behaviour to decide: none: the blueprint already says the case is reported as unwritable (exit 1, the one line `shelf: cannot write shelf.json (EISDIR)`, no stack). A second defensible reading is that TD-11 ("a defect must not be silent") makes the stack intended for any unclassified failure; but a directory in the way of the temporary file is a write failure the store is told to classify, not a defect in shelf.
- Row: none. The draft row `D-1.row.mjs` of the QA run is not carried, by the founder's decision of 2026-10-29 (below): since story 3 (TD-20, main `d01f4a9`) the store names its temporary file `.shelf.json.<pid>.tmp`, so a directory named `.shelf.json.tmp` no longer stands in its way and the trigger seen above is unreachable. A record with no row is a report, not a defect (INCREMENT.md section 9); it is kept so that the number D-1 is never reused and the finding stays on record.
- Severity: wrong refusal
- Found: QA pass of story 2, main a9c2f92, 2026-10-28, by the qa-tester subagent; reproduced by the QA orchestrator, 2026-10-28
- Recommendation: defer; the trigger is a directory the reader made with the store's own temporary-file name, and nothing is lost or changed. The fix would have touched `app/src/store.mjs` only (`writeShelf`'s clean-up must not throw: remove the temporary only when it is a file, or catch the removal's own error and still report unwritable). Blueprint section 12 does not move: section 7 and the message table already describe the intended behaviour; the code departed from them.
- Decision: deferred, 2026-10-28, ajpasco, it only happens when someone makes a directory named .shelf.json.tmp by hand
