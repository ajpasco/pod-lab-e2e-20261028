# D-4: An `add` at the id ceiling succeeds and leaves a shelf every command then refuses as corrupt

- Seen: With `shelf.json` holding `{"nextId": 9007199254740991, "books": []}` (the largest safe integer), `node app/shelf.mjs add Dune` exits 0, prints `added 9007199254740991 Dune`, and writes `"nextId": 9007199254740992` (2^53, not a safe integer). After that, `list`, `add Emma`, `done 9007199254740991` and `drop 9007199254740991` each exit 1 with `shelf: shelf.json is not a shelf (nextId is not a positive integer); fix or remove it` on stderr and nothing on stdout. The reader's log is refused by shelf itself after a command shelf reported as a success. Cause, read in `app/src/store.mjs` and `app/src/shelf.mjs`: `add` assigns `nextId` and stores `nextId + 1` without a ceiling, and the shape check `isPositiveInteger` uses `Number.isSafeInteger`, so the document shelf just wrote fails its own check.
- Requires: PRD section 4, Corrupt shelf file ("valid JSON that is not what shelf itself writes"): a file shelf wrote on a successful command must not be refused as corrupt; REQ-01 c1 and c2 (a successful `add` gives the next id and the shelf stays usable). The PRD says nothing about an id ceiling: it is silent on what `add` does when the next id cannot be represented.
- Behaviour to decide: the PRD is silent on the ceiling. Defensible: (a) refuse the `add` that would need an id above the largest safe integer (exit 1, a message on stderr, nothing on stdout, file untouched); (b) accept a `nextId` of exactly 2^53 in the shape check and refuse the next `add`; (c) leave it and record it as an accepted limitation. Recommended, if it is fixed: (a). The founder deferred it (below), so no behaviour is chosen yet and the PRD gains no criterion.
