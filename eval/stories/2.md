## What to build

- `done <id>`: sets the book's status to "read" and prints exactly `done <id> <title>`, exit 0. A
  book already read is marked read again: the same line, exit 0, the book stays read (REQ-03 c3).
  Other books are unchanged.
- `drop <id>`: removes the book and prints exactly `dropped <id> <title>`, exit 0. Other books keep
  their ids, statuses and titles; a dropped id is never reused (the store's next id is not lowered).
- The id, for both (PRD section 4, Numeric id, Missing id, Unknown id; Order of checks): the command
  word is checked, then the id, before `shelf.json` is read. A missing id or a non-numeric id (`abc`,
  `1.5`, `-1`, `1a`, `+1`, `""`) is refused with exit 2 and a message on stderr. A numeric id is a
  string of decimal digits and denotes the number it spells: `007` is book 7, and prints `7`. An
  unknown id (`99`, `0`, `007` with no book 7, any id when there is no `shelf.json`) is refused with
  exit 1 and a message on stderr, and creates no file. Extra arguments after the id are ignored.
- A refused `done` or `drop` prints nothing on stdout and leaves `shelf.json` untouched (byte for
  byte; still absent when it was absent). A file error (unreadable, corrupt, unwritable: exit 1)
  is reported only when the id passed its check.
- The `unknown-id` kind in the boundary's exit-code table: exit 1 (blueprint section 10).
- Messages as blueprint section 10's table fixes them; the rows check only that stderr is
  non-empty.
