# Story 1: add, list, the unknown-command path and the store

Branch: `story/1`. One story per branch.

## What to build

- `add`: takes the rest of the arguments as the title, trims it, refuses an empty or blank title
  (exit 2), gives the book the next id and prints `added <id> <title>`.
- `list`: prints the books in ascending id order, one line each: `<id> <status> <title>`.
- The unknown-command path: an unknown word, or no word, is refused (exit 2) with the usage on
  stderr. `done` and `drop` are not routed yet and fall to this path; the usage text already names
  all four commands (`add`, `list`, `done`, `drop`).
- The store, complete: a missing `shelf.json` is an empty shelf and creates nothing; an unreadable,
  corrupt or unwritable file is refused (exit 1); the write method of the blueprint (section 7).
  Story 2 never edits the store.
- The error class, and the boundary: argv in, stdout and stderr and the exit code out, the usage
  text and the exit-code table (blueprint section 10).

## Files it creates

- `app/shelf.mjs` (boundary)
- `app/src/shelf.mjs` (rules)
- `app/src/store.mjs` (store)

Nothing else under `app/`. No `package.json`, no test file.
